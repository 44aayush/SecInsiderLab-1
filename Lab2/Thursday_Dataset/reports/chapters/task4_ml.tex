\chapter{Task 4: Machine Learning Classifiers}\label{chap:task4_ml}

\section{Setup}\label{sec:ml-setup}

We train Logistic Regression (LR, \texttt{max\_iter=5000}) and a Decision Tree (DT, \texttt{random\_state=42}, unpruned) with scikit-learn~\cite{pedregosa2011sklearn}. Each is trained in two variants, default and \texttt{class\_weight="balanced"}, and for two targets: binary (BENIGN vs.\ ATTACK) and multiclass (four labels). This gives eight models. Every model is one scikit-learn \texttt{Pipeline}: \texttt{MinMaxScaler(clip=True)}, \texttt{SelectKBest(chi2, k=20)} and the classifier (Listing~\ref{lst:pipe}). Scaler and selector are fitted on the training split only (114,925 flows). All models are evaluated on the held-out test split of 49,254 flows, of which 643 are attacks. The selected features of every saved pipeline equal the Task 3 lists exactly, and all four LR models converged well below the iteration limit. Inference time is the median of five timed \texttt{predict} calls on the whole test split after one warm-up call, scaled to 1,000 flows.

\section{Binary Results}\label{sec:ml-binary}

The default Decision Tree is the best binary model (Table~\ref{tab:t4binary}): it detects all 643 attacks (recall 1.0000) with 18 false positives and an attack F1 of 0.9862. Its balanced variant is almost identical. Logistic Regression does worse in both variants. The default LR misses 94 attacks (recall 0.8538). With \texttt{class\_weight="balanced"}, LR reaches a recall of 0.9907, but its precision drops to 0.2349. It raises 2,075 false alarms, ten times as many as the default LR (201). Figure~\ref{fig:cm} (a) and (b) show the confusion matrices of the default DT and the balanced LR.

\section{Multiclass Results}\label{sec:ml-multi}

In the multiclass setting, the default Decision Tree again leads, with a macro-F1 of 0.7290 (Table~\ref{tab:t4multi}). The default Logistic Regression reaches an accuracy of 98.54\,\% but detects \emph{no} attack at all (F1 of 0.0000 for all three attack classes, macro-F1 0.2482): it predicts almost everything as BENIGN (Figure~\ref{fig:cm} (d)). This is the accuracy paradox, since 98.7\,\% of the data is benign anyway. Class weighting raises the LR macro-F1 only to 0.3191 and lowers the DT macro-F1 to 0.5642. Within the DT, Brute Force and XSS are frequently confused (Figure~\ref{fig:cm} (c)): 103 Brute Force flows are predicted as XSS and 97 XSS flows as Brute Force. Both attacks are automated HTTP requests from the same client to the same web server, and flow statistics cannot see the payload, which is the only thing that really differs. SQL injection reaches an F1 of 0.9091, but with only 6 test flows (5 detected) this number is statistically weak: one flow more or less changes it by about 0.1.

\section{Interpretation}\label{sec:ml-interp}

The Decision Tree beats Logistic Regression on both targets: attack F1 of 0.986 against at best 0.788, and multiclass macro-F1 of 0.729 against 0.319. Attacks occupy narrow value ranges of a few features (small TCP windows, port 80, flag counts), and a tree isolates such ranges with axis-aligned thresholds. LR draws a single linear boundary through heavy-tailed, min-max-compressed features and cannot. Class weighting buys LR recall at the price of precision; for the DT it hardly changes the binary result and hurts the multiclass result. The binary Decision Tree (default) is the model we use in the real-time part.
